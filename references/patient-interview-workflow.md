# 生成患者调研访谈

沿用参考技能“生成深度访谈”的患者筛选、研究方式、内容来源和模板克隆方法；“生成患者调研访谈”为当前技能的主触发词，“生成深度访谈”为兼容触发词。

## 请求

```text
生成患者调研访谈
调研时间：2026年9月
调研数量：10人
调研方式：深度访谈
是否轻度：否
依据以下文件：
/绝对路径/月度患者清单.xlsx
/绝对路径/患者随访.xlsx
/绝对路径/症状自评.xlsx
/绝对路径/用药提醒.xlsx
/绝对路径/不良反应清单.xlsx
```

参数分行填写。调研时间和正整数人数必填；时间支持 `YYYY年M月`、`YYYY-MM`、`YYYY-MM-DD` 或 `YYYY-MM-DD 至 YYYY-MM-DD`，使用明确的闭区间，不推断含糊日期。调研方式省略时为“深度访谈”，只接受“电话随访”或“深度访谈”，兼容 `=`、`：`、`:`；调研方式显式空值、非法值或重复填写时报错。是否轻度省略时为“否”，只接受“是/否”。

默认使用月度患者清单、患者随访、症状自评、用药提醒、不良反应清单五表。兼容旧版患者主表、健康管理方案、跟踪提醒、智能随访、症状自评及不良反应清单六表；不混合两种组合。表头按角色识别，路径还原重复的 `\_`、`\.` 及行末反斜杠。没有不良反应清单不能确立受访资格；严重程度支持“高度（3级）”等带等级文本。产品从当前请求、同一任务已知产品或源表中核实，不继承模板产品。

**默认模拟授权已开启，无需人工确认。** 用户调用“生成患者调研访谈”或“生成深度访谈”即可按源资料编写完整AI模拟问答及对应主题分析，不需要额外填写“AI生成”，不要求真实原文，不改交付为待填写提纲。解析结果默认 `dialogueMode=simulated`、`simulationAuthorized=true`。可选 `内容模式：模拟访谈 / 真实访谈 / 访谈提纲`；明确要求真实记录或仅提纲时尊重用户选择，真实模式不得拿模拟内容补缺。此默认只授权情景文档生成，不授权联系患者、改写源数据或对外发布。

可在文件列表后增加 `输出文件模板：`，其后每行一个 DOCX 路径。深度访谈的自定义模板必须成对提供；电话随访接受一份明细模板或原有两份模板，按内容识别并只用明细。省略时用内置模板：

- `assets/patient-interview-analysis-template.docx`
- `assets/patient-interview-records-template.docx`

## 执行

1. 全文读取 [deep-interview-template-contract.md](deep-interview-template-contract.md)，并读取本次所需模板。保存请求至独立工作目录，运行：

   ```bash
   node scripts/parse_report_request.mjs --input WORK/request.txt --output WORK/request.json
   python scripts/prepare_interview_sources.py --request WORK/request.json --output WORK/interview-sources.json
   ```

2. 准备脚本按调研周期筛选随访、自评和不良反应记录，按患者ID关联所有资料。患者主表ID非空唯一；明细排除主表外患者并记录排除数；同一患者多条事件取最高严重度，`高度/重度`统一为高度。默认仅中度和高度；允许轻度时先高度、再中度、最后轻度补足，同严重度保留患者主表顺序。人数不足时报告可选数与需求数并停止，不减少请求人数或编造受访者。患者标签、洞察风险评分不能代替事件严重度。
3. `interview-sources.json` 给出受访资格、源资料及内容模式。默认 `simulated` 时直接生成完整情景，无需再次索取授权或真实访谈原文。只有用户明确要求 `actual` 才按真实访谈文本核对日期、方式、轮次及原话；明确要求 `outline` 时生成待填写提纲。Excel随访次数不是访谈轮数，随访日期不是实际访谈日期。
4. 模拟文件名必须包含“模拟”，交付说明及内部核验记录标明情景性质。日期与问答可以在本次调研周期内设计，但不得将情景当作已经完成的真实访谈；源记录中的不确定性继续保留，不将待核实症状写成医学确诊，不编造已就医、已执行干预或已经好转等源文件未支持的结果。问答需结合逐人疾病、实际登记用药、症状和生活场景；未匹配方案时核对用药，不从其他患者复制药物。源表冲突作为中性追问，不擅自裁定某份数据正确。所有分析人数和引语从最终模拟明细汇总。
5. 先提取每个选用模板的 SHA256、ZIP 部件、节属性、样式、段落/run、表格行/单元格、页眉页脚及关系。复制各自模板包并克隆其匹配节点，在 `word/document.xml` 内写入当次内容；不得从空白 Word 重建或套用洞察报告构建器。内置模板的其他ZIP部件按字节保留；自定义模板有页眉等旧产品信息时记录必要额外修改。保留字体、字号、固定行距、表格原始列宽、底纹、边框、合并关系与页码。
6. 深度访谈的分析报告包含“一、调研概述”“二、核心发现”“三、改进建议”。核心发现通常3–5条，按主题组织“现象描述、数据支撑、原话引用、分析”，不按轻中重分组比较；建议通常1–2条。真实证据不足时不凑发现。所有主题人数和引语都从本次最终访谈明细汇总。
7. 明细包含概况表和逐人记录：完整患者ID、编号、日期、方式、实际轮次、核心反馈摘要、引语和逐轮问答。内置7轮结构可用于默认模拟情景；真实访谈按实际轮次写。逐人另起页，短行避免跨页，不压缩字号、平均列宽或固化模板人数。电话模式全文使用“电话随访”和“一对一电话随访记录”，不残留线上深度访谈文案。用户要求建议“无”时保留栏目并填写“无”；情景不主动添加平台投诉或功能诉求，真实意见不能篡改。
8. 按 `outputKinds` 核对交付数量：电话随访仅1份 `<产品>_患者访谈记录明细_<YYYY-MM>[_模拟].docx`；深度访谈2份，另含 `<产品>_患者访谈分析报告_<YYYY-MM>[_模拟].docx`。年月取调研周期开始日期。默认输出患者主表同级目录，不可写时使用任务输出目录；重名追加时间戳，不覆盖旧文件。
9. 按模板契约完成内容对账、引用定位、样例残留检查、OOXML属性及包部件比较，并用可用 documents 渲染器逐页检查全部输出。只有结构与视觉检查均通过才能声称“严格按模板生成并已检查”。渲染不可用时如实说明未完成视觉核验及原因，保留核验记录；格式规范、源数据、预览不作为访谈成品交付。

中文渲染出现缺字时，按 [洞察报告流程的字体配置](insight-report-workflow.md#macos-渲染器的中文字体配置) 在本次任务内解决字体发现问题，不替换模板字体。
