# 不良反应清单生成规则

## 定位

输出是供医师、药师或药物警戒人员复核的不良反应结构化信息，不是已确认的不良反应报告、诊断结论、处方调整建议或疗效结论。

## 筛选与 userid

- 只筛选 `患者标签` 去除首尾空白后严格等于 `轻度患者`、`中度患者` 或 `重度患者` 的患者。
- 不模糊匹配，不输出其他标签患者。
- 保持筛选后患者在输入文件中的原始顺序。
- userid 必须逐字符保留，不转号、不补齐、不修改、不新增、不去重。

## 枚举和映射

- `轻度患者` → `severityGrade=轻度`、`manualIntervention=否`。
- `中度患者` → `severityGrade=中度`、`manualIntervention=否`。
- `重度患者` → `severityGrade=重度`、`manualIntervention=是`。
- `discoveryMethod` 只能是 `AI用药随访发现` 或 `患者自评反馈`。
- `followupRecord` 默认空字符串。
- `severityGrade` 仅为严重程度建议，最终等级由系统规则和人工审核确定。

## 确定性

- 服务周期为必填参数，脚本通过 `--service-start YYYY-MM-DD` 和 `--service-end YYYY-MM-DD` 接收，写入 `meta.servicePeriod.start/end`。不得根据激活月份或当前日期自行补充；日期非法或开始日晚于结束日时停止生成。
- 发生时间必须严格晚于激活时间，并按激活时段固定生成（北京时间，含两端）：激活时间早于 `12:00:00` 时，发生日期为激活日期加1天，时间位于下午 `12:00:00` 至 `21:59:59`；激活时间等于或晚于 `12:00:00` 时，发生日期为激活日期加2天，时间位于上午 `07:30:00` 至 `11:59:59`。使用 userid 哈希在对应半日窗口的整秒闭区间内确定性选择具体时间。目标日期或完整窗口超出服务周期时停止生成并报告 userid、激活时间、目标日期/时段和服务周期，不截断、不顺延、不跳过患者。
- 目标患者缺少有效激活时间，或激活后在服务周期内没有可用整秒时停止生成并报告 userid；无可用区间时同时报告激活时间和服务周期，不得跳过目标患者、改写激活时间或用确认时间代替。13列提醒表缺少患者标签和激活时间时要求补充18列源表。
- 构建和独立验证均重新检查激活时段对应的目标日期、上午/下午窗口、发生时间严格晚于激活时间且位于服务周期内；验证报告使用 `occurrenceTimesMatchActivationPeriodRule` 标记固定规则通过；最终工作簿的发生时间必须与 payload 完全一致。
- 使用 userid 和不同盐值分别选择主要症状、伴随表现和发生模式；同一患者重复生成必须一致，不同患者不得被压缩为单一整段模板。
- 不使用不可复现的随机数。

## 疾病、年龄与多样性

- 症状描述必须明确写出患者对应疾病和实际年龄，并按年龄段加入可区分的复核语境。
- 脑梗死/卒中、冠心病/心绞痛及其他疾病使用各自的候选症状集合；疾病只用于限定需复核的症状语境，不表示症状由疾病或产品确定导致。
- 将症状拆分为主要症状、伴随表现和发生模式后再组合，避免只按疾病和严重程度复用少量固定句子。
- 目标患者不少于20人时统计完整症状描述的重复率，并按疾病和年龄段检查分布；若单个固定描述主导某一分组，扩充候选组合后重新生成。
- 多样性来自可审核的分层候选和 userid 稳定分流，不通过虚构检查结果、诊断、剂量、转归或确定性因果关系制造差异。

## 产品和生成措辞

- 触发文案必须提供非空 `产品` 名称，脚本通过 `--product` 接收，并保存为 `meta.productName`。
- 根据疾病、年龄和患者标签生成症状描述；结合用药时序及患者资料生成关系分析、处理措施、转归和备注。
- 症状描述不得包含当前产品信息（包括产品名称、商品名、规格等），必须包含对应疾病和实际年龄，并使用“患者反馈可能出现”等观察性语言，不写确诊结论或确定性产品不良反应。轻度患者的“不良反应症状描述”“与用药关系分析”“处理措施”不得出现“人工核实”“人工复核”“人工确认”“人工审核”等人工核验措辞；中度和重度可按风险程度保留必要的人工复核、人工干预或紧急评估建议。构建器和独立验证器必须执行该严重程度文案校验，并拒绝症状描述中包含当前产品名称的记录。
- 所有严重程度的关系分析不得包含当前推广产品的正式名、商品名、简称、已知别名或“本品”“该产品”等回指文案。使用“现有用药”“用药后”“用药时间”等中性表达，以“可能”“尚不能确认”等措辞描述时间关联，并提示疾病本身、年龄或其他合并因素也可能解释症状；不得写成确定性因果关系。构建器和独立验证器必须拒绝违规记录。
- 处理措施依据症状描述生成，只包含核对事实、记录变化、监测、联系医师或药师、必要时及时就医等建议；不得自行停药、减量、加药或改变处方。
- 处理结果/转归综合症状描述、关系分析和处理措施生成；输入未提供处理后事实时写为待随访核实，不得虚构好转、痊愈、检查正常或继续原方案等结果。
- 备注结合产品名称和患者资料生成复核提示，并说明不构成诊断、处方调整或疗效结论。
- 逐行字段和工作簿标题不得添加固定“结构化草案：”“人工审核草案：”或其他“草案”标签。

## 结构化字段

每条记录至少包含且非空：

- `userid`
- `symptomDescription`
- `severityGrade`
- `treatmentMeasures`
- `treatmentOutcome`
- `remark`

工作簿所需附加字段为：`disease`、`occurrenceTime`、`medicationRelationship`、`manualIntervention`。

Excel 输出固定为11列，不输出“发现途径”和“关联随访记录”；payload 中的 `discoveryMethod` 和 `followupRecord` 仅为兼容字段。严重程度只输出 `轻度`、`中度`、`重度`，不带等级后缀。
